# 하드 의존성에만 명시적인 `/setup-me-skills` 포인터

엔지니어링 스킬은 `/setup-me-skills`가 심어 둔 저장소별 설정(이슈 트래커, 트리아지 라벨 어휘, 도메인 문서 레이아웃)에 의존합니다. 어떤 스킬은 그 설정 없이는 의미 있게 동작할 수 없습니다. 특정 이슈 트래커에 게시하거나 특정 라벨 문자열을 적용해야 하기 때문입니다. 다른 스킬은 출력을 날카롭게 하는 데(어휘, ADR 인지)만 쓰고 없어도 부드럽게 성능이 저하됩니다.

이를 **하드 의존성** 스킬과 **소프트 의존성** 스킬로 나눕니다.

- **하드 의존성** (`to-tickets`, `to-spec`, `triage`): 명시적인 한 줄을 넣습니다. _"… 이미 제공되어 있어야 합니다. 그렇지 않다면 `/setup-me-skills`를 실행하세요."_ 매핑이 없으면 출력이 모호한 정도가 아니라 틀립니다.
- **소프트 의존성** (`diagnose`, `tdd`, `improve-codebase-architecture`): "프로젝트의 도메인 용어집"과 "건드리는 영역의 ADR"을 모호한 산문으로만 언급합니다. 문서가 없어도 스킬은 동작하며, 출력이 덜 날카로울 뿐입니다.

이렇게 나누면 소프트 의존성 스킬은 토큰이 가볍게 유지되고, 설정 포인터가 하중을 받지 않는 곳에 맹목적으로 따라 붙는 것을 피할 수 있습니다.
