# 권한 모드 (Permission mode)

> 도구와 환경

에이전트 모드 중 권한 관문에 해당하는 부분. 어떤 도구 호출이 권한 요청을 촉발하고 어떤 것이 자동으로 실행되는지 정합니다.

[에이전트 모드](./agent-mode.md) 중 권한 관문에 해당하는 부분으로, 어떤 [도구 호출](./tool-call.md)이 [권한 요청](./permission-request.md)을 촉발하고 어떤 것이 자동으로 실행되는지 정합니다. [하니스](./harness.md)가 그 위에 행동 지침을 묶기 시작하기 전, 모드 시스템의 원래 목적이었습니다.

하니스는 이런 모드의 사다리를 제공합니다.

| 모드 | 읽기 | 쓰기와 셸 | 전형적인 용도 |
| --- | --- | --- | --- |
| 읽기 전용 / 계획 | 자동 | 차단 | 조사, 계획, 검토 |
| 기본 | 자동 | 묻기 | 일상적인 감독 작업 |
| 자동 편집 | 자동 | 편집은 자동, 셸은 묻기 | 신뢰하는 저장소, 기계적 변경 |
| "Yolo" / 완전 자동 | 자동 | 자동 | [샌드박스](./sandbox.md), [AFK](./afk.md) 실행 |

사다리의 한 칸을 고르는 것은 안전과 방해 사이의 거래이며, 두 실패 모드 모두 체감됩니다. 너무 빡빡하면 당신이 병목이 됩니다. [에이전트](./agent.md)가 무해한 읽기에도 몇 초마다 멈추고, 당신은 자동 조종으로 승인을 누르게 되며, 승인이 아무 의미도 없어집니다. 무심코 도장 찍기는 최악의 조합으로, 방해는 모두 겪으면서 보호는 전혀 받지 못합니다. 너무 느슨하면 에이전트가 먼저 보고 싶었을 파일을 편집하고 명령을 실행합니다.

느슨한 쪽은 샌드박스 안에서 가장 정당화됩니다. 잘못된 [도구](./tool.md) 호출의 피해 반경이 억제되기 때문입니다. 샌드박스 밖에서는 대부분 읽기를 자동 승인하고, 되돌릴 수 없는 것에는 [사람이 개입](./human-in-the-loop.md)하게 두는 선에서 정착합니다.

_사용 예:_

"grep마다 멈춰서 AFK 실행이 완전히 망했어요."

"읽기 전용 도구에 대한 권한 모드는 풀고, 쓰기와 셸에서는 계속 묻게 하세요. 조사 [세션](./session.md)의 권한 요청 대부분은 잡음이에요."
