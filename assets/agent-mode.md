# 에이전트 모드 (Agent mode)

> 도구와 환경

권한 모드와 시스템 프롬프트에 주입되는 행동 지침을 묶은 프리셋. 세션 도중에 바꿀 수 있습니다.

[에이전트](./agent.md)가 실행 중에 동작하는 방식을 정하는 프리셋으로, [권한 모드](./permission-mode.md)와 [시스템 프롬프트](./system-prompt.md)에 주입되는 행동 지침을 함께 묶습니다. 예: 위험한 호출에서 묻는 기본 모드, 편집을 막고 에이전트를 조사 쪽으로 이끄는 **계획 모드(plan mode)**, 편집을 자동 승인하는 **편집 수락(accept-edits)** 모드, 모든 것을 자동 승인하는 **권한 우회(bypass permissions)** 모드(속칭 **YOLO 모드**). [세션 도중](./session.md)에 바꿀 수 있습니다.

이 묶음이 모드와 단순한 권한 설정을 가릅니다. 권한 모드는 관문일 뿐이며, 어떤 [도구 호출](./tool-call.md)이 통과할지만 정합니다. 관문만 있으면 편집하고 싶지만 할 수 없는 에이전트가 됩니다. 쓰기를 제안하고, 막히고, 다른 방법을 시도합니다. 주입된 지침은 그 바람을 없앱니다. 계획 모드는 편집을 막기만 하는 것이 아니라 에이전트에게 지금이 계획 단계라고 알려 주므로, 관문에 맞서 애쓰는 대신 읽고, 묻고, 제안합니다. 관문과 조향이 같은 방향을 가리킵니다.

실제로는 작업 도중 신뢰가 변하면서 모드를 바꿉니다. 같은 작업이 여러 모드를 거칠 수 있습니다. 접근법을 잡는 동안은 계획 모드, 처음의 민감한 편집에는 묻는 기본 모드, 에이전트가 변경을 이해했음을 보인 뒤에는 편집 수락, [샌드박스](./sandbox.md) 안의 [AFK](./afk.md) 실행에는 우회 모드. 모드를 바꾸는 데는 비용이 들지 않습니다. 대화는 정확히 그 자리에서 새 권한과 새 지침으로 이어집니다. 모든 프롬프트를 읽지도 않고 승인하고 있다면 모드가 실제 신뢰보다 빡빡하게 설정된 것이고, 계속 편집을 거절하고 있다면 더 느슨하게 설정된 것입니다.

_벤더별 용어:_ Claude Code는 이를 "permission modes", Codex는 "approval modes"라고 부릅니다. 둘 다 행동 지침을 묶기 이전부터 있던 이름입니다.

_사용 예:_

"계획만 원하는데 자꾸 파일을 편집해요."

"계획 모드로 바꾸세요. 쓰기를 막고 조사에 머뭅니다."

"나중에 AFK로 돌릴 때는요?"

"우회 모드로 하되, 샌드박스 안에서만요."
