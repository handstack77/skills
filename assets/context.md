# 컨텍스트 (Context)

> 세션, 컨텍스트 창, 턴

에이전트가 지금 접근할 수 있는 관련 정보. 작업에 적절한 것 중 에이전트가 아는 것.

[에이전트](./agent.md)가 지금 접근할 수 있는 관련 정보. 추상 명사입니다. 모델이 보는 원시 입력([컨텍스트 창](./context-window.md))도 아니고, 누적되는 이력([세션](./session.md))도 아니며, _작업에 적절한 것 중 에이전트가 아는 것_입니다. "컨텍스트에 로드한다"는 것은 이 집합의 일부로 만든다는 뜻이고, "컨텍스트 엔지니어링"은 이를 선별하는 분야입니다.

세 용어는 깔끔하게 나뉩니다.

| 용어 | 가리키는 것 |
| --- | --- |
| 컨텍스트 | 에이전트가 현재 가진, 작업과 관련된 정보 |
| 컨텍스트 창 | 요청마다 모델이 보는 실제 [토큰](./token.md) 시퀀스 |
| 세션 | [하니스](./harness.md)가 저장하는 진행 중인 대화 |

이 구분이 중요한 것은 컨텍스트가 양이 아니라 질의 척도이기 때문입니다. 컨텍스트 창이 거의 가득 찼는데도 컨텍스트는 나쁠 수 있습니다. 눈앞의 작업과 무관한 오래된 도구 출력 수천 토큰이 그렇습니다. 반대로 거의 비었는데 컨텍스트가 훌륭할 수도 있습니다. 작업이 좌우되는 그 타입 정의 하나가 있을 때입니다.

일상의 실패 대부분은 컨텍스트로 거슬러 올라갑니다. 에이전트가 API를 지어내거나, 결정을 어기거나, 스키마를 짐작할 때 첫 질문은 그때 컨텍스트에 무엇이 있었느냐입니다. 보통은 관련 사실이 아예 로드되지 않았거나, [주의 저하](./attention-degradation.md) 속에 묻혀 있었습니다. 해법은 선별입니다. 작업에 필요한 것을 로드하고 필요 없는 것은 두지 않습니다.

_사용 예:_

"타입에 없는 필드를 계속 지어내요."

"타입 파일이 컨텍스트에 없어서 호출 지점을 읽고 짐작하고 있어요. 정의부터 읽게 하세요."
