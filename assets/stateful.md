# 상태가 있음 (Stateful)

> 세션, 컨텍스트 창, 턴

정보를 앞으로 가져갑니다. 세션은 턴을 넘어 상태가 있고, 에이전트는 기억 시스템으로 세션을 넘어 상태를 갖게 만들 수 있습니다.

정보를 앞으로 가져갑니다. [세션](./session.md)은 [턴](./turn.md)을 넘어 상태가 있습니다. 세션이 진행되면서 [컨텍스트](./context.md)가 쌓이고, 그래서 긴 세션은 [바보 구간](./smart-zone.md)으로 흘러듭니다. [에이전트](./agent.md)는 정보를 [환경](./environment.md)에 저장하고 이후 세션 시작 때 다시 로드하는 [기억 시스템](./memory-system.md)을 더해 **세션**을 넘어 상태를 갖게 만들 수 있습니다. [모델](./model.md)은 결코 상태가 없으며, 겉보기의 연속성은 [하니스](./harness.md)가 컨텍스트를 다시 넣어 주는 것입니다. [상태가 없음](./stateless.md)의 짝입니다.

각 계층에서 상태가 있는 곳:

| 계층 | 상태가 있나? | 방법 |
| --- | --- | --- |
| 모델 | 절대 없음 | [파라미터](./parameters.md)는 고정되어 있고, 각 요청에 든 것만 봅니다 |
| 세션 | 턴을 넘어 | 하니스가 모든 메시지와 [도구 결과](./tool-result.md)를 컨텍스트에 덧붙입니다 |
| 하니스 | 세션을 넘어 | 기억 파일, [AGENTS.md](./agents-md.md), [핸드오프 산출물](./handoff-artifact.md). 적어 두었다가 나중에 다시 로드합니다 |
| 환경 | 항상 | 세션이 실행 중이든 아니든 파일은 남습니다 |

각 계층의 상태는 한 계층 아래에 저장된 것을 다시 읽어서 만들어집니다. 세션이 연속적으로 느껴지는 것은 하니스가 상태 없는 모델에 메시지 이력을 다시 보내기 때문이고, 에이전트가 세션을 넘어 기억하는 것은 하니스가 환경에서 파일을 다시 로드하기 때문입니다. 모델 자체에는 어떤 상태도 저장되지 않습니다.

상태가 항상 바람직한 것은 아닙니다. 앞으로 가져간 모든 것이 다음에 올 것에 영향을 주므로, 세션 초반에 한 잘못된 가정도 함께 가져갑니다. [비우기](./clearing.md)는 세션 상태를 일부러 버리고 적어 둔 것에서 다시 시작하는 행위입니다.

_사용 예:_

"어제의 제 선호를 기억하던데, 모델이 그걸 학습했다는 뜻인가요?"

"아니요, 하니스가 그것을 기억 파일에 쓰고 세션 시작 때 다시 로드했기 때문에 에이전트에게 상태가 있는 거예요. 모델 자체는 어제 일을 전혀 보지 못했습니다."
