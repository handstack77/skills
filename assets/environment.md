# 환경 (Environment)

> 도구와 환경

에이전트가 작용하는 세계. 하니스 밖의 모든 것으로, 에이전트는 도구 결과로 인지하고 도구 호출로 바꿉니다.

[에이전트](./agent.md)가 작용하는 세계입니다. [하니스](./harness.md) 밖의 모든 것으로, 에이전트는 [도구 결과](./tool-result.md)로 인지하고 [도구 호출](./tool-call.md)로 바꿉니다. 하니스는 에이전트를 _실행하고_, 환경은 에이전트가 _일하는 곳_입니다. [`AGENTS.md`](./agents-md.md) 같은 파일은 환경에 있고, 그것을 [컨텍스트 창](./context-window.md)에 로드하는 것은 하니스입니다. [파일 시스템](./filesystem.md)이 가장 흔한 환경이지만 유일한 것은 아닙니다. 데이터베이스, 원격 API, 브라우저 세션도 모두 환경이 될 수 있습니다.

에이전트는 들여다볼 때만 환경을 봅니다. 환경에 대해 아는 모든 것은 도구 결과로 도착했으므로, 그 그림은 각각 찍은 순간에는 정확했던 스냅샷의 모음입니다. 에이전트가 읽은 뒤에 파일이 바뀌면(당신이 손으로 편집하거나 빌드 단계가 다시 생성하면), 무언가가 다시 읽게 하기 전까지 에이전트는 오래된 사본으로 계속 추론합니다. 에이전트가 더는 그렇게 생기지 않은 파일을 자신 있게 설명한다면 대개 이 경우입니다. 환경은 움직였고 스냅샷은 그러지 않았습니다.

환경은 또한 지속되는 계층이며, 언제나 [상태가 있는](./stateful.md) 유일한 계층입니다. [세션](./session.md)의 컨텍스트는 세션이 끝나면 사라지지만, 환경에 쓰인 파일은 다음 세션이 읽을 수 있도록 남습니다. [기억 시스템](./memory-system.md), [핸드오프 산출물](./handoff-artifact.md), `AGENTS.md`가 이에 기댑니다. 에이전트가 내일도 알아야 하는 것은 무엇이든 환경에 남아야 합니다.

환경의 크기는 당신이 정합니다. [샌드박스](./sandbox.md)는 에이전트가 닿을 수 있는 범위를 제한해 환경을 줄이고, [도구](./tool.md)를 추가하면 데이터베이스나 API를 닿는 범위로 들여와 환경을 넓힙니다. 경계 안에 있는 것이 에이전트가 인지하고 바꿀 수 있는 것이며, 밖에 있는 것은 에이전트에게 존재하지 않습니다. 환경이 에이전트의 작업을 얼마나 잘 뒷받침하도록 갖춰졌는지가 코드베이스의 [AX](./ax.md)입니다.

_피할 표현:_ 런타임이나 하니스 자체를 "환경"이라고 부르는 것. 하니스는 감싸는 것이고 환경은 작업 공간입니다.

_사용 예:_

"에이전트가 스테이징 DB 스키마를 볼 수 없어요."

"환경에 연결해 주세요. 스테이징에서 읽기 전용으로 제한한 `psql` 도구를 주면 됩니다. 하니스는 괜찮고, 작용할 대상이 없을 뿐이에요."
