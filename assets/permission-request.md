# 권한 요청 (Permission request)

> 도구와 환경

미리 승인되지 않은 도구 호출을 실행하기 전에 하니스가 사용자에게 보여 주는 것. 사람을 루프에 넣는 메커니즘입니다.

미리 승인되지 않은 [도구 호출](./tool-call.md)을 실행하기 전에 [하니스](./harness.md)가 사용자에게 보여 주는 것입니다. [모델](./model.md)이 도구 호출을 만들면, 하니스는 즉시 실행하는 대신 멈추고 묻습니다. 승인하면 실행되고, 거부하면 하니스가 거부를 [도구 결과](./tool-result.md)로 모델에게 알립니다. 하니스가 위험하거나 민감한 행동에 [사람을 루프에](./human-in-the-loop.md) 넣는 메커니즘입니다.

권한 요청의 수명 주기:

| 단계 | 주체 | 일어나는 일 |
| --- | --- | --- |
| 1 | 모델 | 도구 호출을 만듦 |
| 2 | 하니스 | [권한 모드](./permission-mode.md)와 저장된 승인에 비추어 확인 |
| 3 | 하니스 | 미리 승인됨: 즉시 실행. 그 밖에는: 멈추고 요청을 보여 줌 |
| 4 | 사용자 | 한 번 승인, [세션](./session.md)의 나머지 동안 승인, 또는 거부 |
| 5 | 하니스 | 호출을 실행하거나 거부를 도구 결과로 돌려보냄 |

요청을 거부하는 것은 에이전트를 조향합니다. 모델은 거부를 다른 도구 결과처럼 읽고 반응합니다. 다른 접근을 시도하거나 무엇을 선호하는지 묻습니다. 대부분의 하니스는 거부에 메시지를 붙일 수 있게 해 주고, 그러면 요청이 조향 지점이 됩니다. "그렇게 말고 마이그레이션 스크립트를 쓰세요"가 모델이 다음에 무엇을 할지 정하는 바로 그 순간에 전달됩니다.

비용은 모든 요청이 당신에 대한 동기식 대기라는 점입니다. [에이전트](./agent.md)는 당신이 답할 때까지 막혀 있습니다. 지켜보는 동안에는 괜찮지만 그렇지 않을 때는 문제입니다. 요청을 끊임없이 촉발하는 에이전트는 [AFK](./afk.md)로 일하게 둘 수 없습니다. 권한 모드가 다이얼입니다. 어떤 호출은 자유롭게 실행하고 어떤 호출은 먼저 묻는지 정하며, 이상적으로는 [샌드박스](./sandbox.md)가 자유 집합을 넓혀도 안전하게 만들어 줍니다.

_사용 예:_

"권한 요청에 10분째 막혀 있어요. 회의 중이었거든요."

"그게 사람이 개입하는 방식의 비용이에요. 안전한 [도구](./tool.md)는 미리 승인해서 정말 위험한 호출에서만 요청이 뜨게 하세요."
