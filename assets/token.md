# 토큰 (Token)

> 모델

모델이 읽고 쓰는 원자 단위. 대략 단어 크기지만 정확히 같지는 않습니다. 컨텍스트 창 크기, 비용, 지연 시간은 모두 토큰으로 셉니다.

[모델](./model.md)이 읽고 쓰는 원자 단위입니다. 대략 단어 크기지만 정확히 같지는 않습니다. 흔한 단어는 토큰 하나이고, 드물거나 긴 단어는 여러 토큰으로 쪼개집니다. [컨텍스트 창](./context-window.md) 크기, 비용, 지연 시간은 모두 토큰으로 셉니다.

텍스트는 토크나이저를 거쳐 토큰이 됩니다. 토크나이저는 [학습](./training.md) 전에 만들어진 수만 개 조각의 고정된 어휘이며, 어떤 입력이든 어휘 항목의 시퀀스로 쪼갭니다. 모델은 문자나 단어를 결코 보지 않습니다. 모든 텍스트는 들어올 때 토큰으로 변환되고, 나갈 때는 [다음 토큰 예측](./next-token-prediction.md)이 출력을 한 번에 토큰 하나씩 만들어 냅니다.

경험칙으로 토큰은 영어 단어의 4분의 3쯤이어서, 1,000토큰은 대략 750단어입니다. 코드는 예측하기 더 어렵습니다. 흔한 키워드와 관용구는 간결하게 토큰화되지만, 생성된 식별자, 해시, base64 덩어리, 압축된(minified) 출력은 "단어"당 여러 토큰으로 쪼개집니다. 패턴은 이렇습니다. 토크나이저의 원천 자료에 자주 나온 텍스트는 짧고 효율적으로 인코딩되고, 그렇지 않은 텍스트는 작은 조각 여러 개로 잘립니다. `a3f9c2e1` 같은 해시는 어디에도 나온 적이 없으므로 여러 토큰으로 쪼개지고, `function`은 토큰 하나입니다. 그래서 작아 보여도 특이한 문자열로 가득한 파일이 컨텍스트 창에서 놀랄 만큼 큰 몫을 차지할 수 있습니다.

토큰은 다른 모든 것을 재는 단위입니다. 비용은 토큰당이며, 제공자는 [입력 토큰](./input-tokens.md)과 [출력 토큰](./output-tokens.md)을 따로 과금합니다. 속도는 초당 토큰이며, 출력이 한 번에 토큰 하나씩 생성되기 때문입니다. 컨텍스트 창은 고정된 토큰 수이므로, 파일의 토큰 수가 얼마나 들어갈지를 정합니다.

_피할 표현:_ "단어": 토큰 경계는 단어 경계와 맞지 않으며, 실제로 중요한 단위는 초당 토큰과 달러당 토큰입니다.

_사용 예:_

"이 프롬프트는 얼마나 클까요?"

"토크나이저에 돌려 보세요. 스키마는 간결하지만 JSON 키가 특이해서 생각보다 많은 토큰으로 쪼개질 거예요."
