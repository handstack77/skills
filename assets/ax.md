# AX

> 작업 패턴

에이전트 경험(agent experience): 에이전트가 좋은 일을 하도록 환경이 얼마나 잘 갖춰졌는가. 검사, 아키텍처, 비어 있는 컨텍스트.

에이전트 경험(agent experience)입니다. 코드베이스에서 [에이전트](./agent.md)가 좋은 일을 하도록 [환경](./environment.md)이 얼마나 잘 갖춰졌는가를 뜻합니다. [DX](./dx.md)의 에이전트 쪽 짝입니다. 같은 에이전트가 한 저장소에서는 잘하고 다른 저장소에서는 못할 때(같은 [모델](./model.md), 같은 [하니스](./harness.md)), 차이는 보통 AX입니다. 본능은 모델을 탓하거나 프롬프트를 다시 쓰는 것이지만, 해법은 저장소에 있는 경우가 더 많습니다.

좋은 AX에는 세 가지 주요 차원이 있습니다.

| 차원 | 좋은 AX의 모습 |
| --- | --- |
| 자동 검사 | 에이전트가 사람 없이 스스로 교정할 수 있는, 빠르고 결정적인 [자동 검사](./automated-check.md): 타입, 테스트, 린트 |
| 아키텍처 | 모든 것을 읽지 않고도 에이전트가 탐색할 수 있는 코드베이스: 예측 가능한 구조, 작은 인터페이스 뒤에 있는 많은 동작, 하는 일을 말해 주는 이름 |
| 비어 있는 컨텍스트 | [AGENTS.md](./agents-md.md), [스킬](./skill.md), [도구](./tool.md)를 간결하게 유지해 [컨텍스트 창](./context-window.md)의 대부분을 작업에 쓸 수 있고, 에이전트가 허우적대지 않고 [스마트 존](./smart-zone.md)에 머묾 |

AX와 DX는 겹칩니다. 좋은 검사와 깔끔한 아키텍처는 두 독자 모두에게 도움이 됩니다. 하지만 갈라지기도 합니다. 사람은 부족 지식, 느린 CI, "청구 모듈은 Sarah에게 물어봐"를 견디지만 에이전트는 그럴 수 없습니다. 에이전트는 IDE 툴팁이나 예쁜 대시보드의 덕을 보지 못하며, 실패가 [도구 결과](./tool-result.md)의 텍스트로 필요합니다. 코드베이스는 DX는 좋고 AX는 나쁠 수 있습니다.

_피할 표현:_ AX를 DX의 동의어로 취급하는 것. 독자가 달라서 필요한 투자도 다릅니다.

_사용 예:_

"에이전트가 API 저장소에서는 훌륭한 코드를 쓰고 프런트엔드에서는 쓰레기를 써요."

"API 저장소에는 엄격한 타입과 빠른 테스트 스위트가 있고, 프런트엔드에는 둘 다 없고 항상 로드되는 스킬이 마흔 개 있어요. 모델 문제가 아니라 AX 격차입니다."
