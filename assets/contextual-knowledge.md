# 맥락적 지식 (Contextual knowledge)

> 실패 모드

에이전트가 지금 컨텍스트에서 직접 읽을 수 있는 사실. 파라미터 지식의 짝.

[에이전트](./agent.md)가 지금 [컨텍스트](./context.md)에서 직접 읽을 수 있는 사실입니다. 사용자의 작업, 에이전트가 읽어 들인 파일, [도구 결과](./tool-result.md), [세션](./session.md) 시작 때 로드된 [AGENTS.md](./agents-md.md) 내용 등입니다. [파라미터 지식](./parametric-knowledge.md)의 짝입니다. 파라미터 지식은 파라미터에서 _회상_하는 것이고, 맥락적 지식은 [창](./context-window.md)에서 _읽는_ 것입니다. 에이전트가 맥락적 지식으로 일할 때는 [환각](./hallucination.md)이 훨씬 드뭅니다. 답이 흐릿한 기억에서 끌려 나오는 것이 아니라 바로 눈앞에 있기 때문입니다.

두 종류의 지식 중 당신이 통제할 수 있는 것은 맥락적 지식뿐입니다. 파라미터는 고정되어 있으므로, [모델](./model.md)에게 없는 지식(사내 SDK, [지식 컷오프](./knowledge-cutoff.md) 이후에 나온 라이브러리, 어제 내린 결정)을 주는 유일한 방법은 컨텍스트에 넣는 것입니다. 실용적인 [AI](./ai.md) 코딩 작업의 상당수는 이것으로 환원됩니다. 모델이 필요로 하는 순간에 올바른 사실을 눈앞에 놓는 것.

맥락적 지식과 파라미터 지식이 충돌하면 보통 맥락적 지식이 이깁니다. 현재 API 문서를 붙여 넣으면 모델은 옛 API에 대한 낡은 기억 대신 그것을 따릅니다. 다만 특히 긴 세션 깊숙한 곳에서는 옛 버전이 여전히 배어 나올 수 있습니다. 문서가 로드되어 있는데도 에이전트가 오래된 패턴으로 계속 되돌아간다면, 파라미터 지식이 맥락적 지식을 뚫고 새어 나오는 것입니다. 교정을 다시 말하거나 작업에 더 가까이 옮기면 도움이 됩니다.

파라미터 지식과 달리 맥락적 지식은 쓰는 데 비용이 듭니다. 창에 로드한 모든 것은 [토큰](./token.md)을 쓰고 모델의 [주의 예산](./attention-budget.md)을 다투므로, 더 많이 로드한다고 자동으로 좋아지지 않습니다. 목표는 모든 사실이 아니라 관련된 사실이 창에 있는 것입니다.

_이 용어를 꺼내는 때:_ 파라미터 지식과 대비할 때만. 그 밖에는 그냥 **컨텍스트**라고 하세요.

_피할 표현:_ "작업 기억": 맥락적 지식은 _지금_ 창에 있는 것이고, [기억 시스템](./memory-system.md)은 세션을 넘는 내용을 창에 넣어 주는 것입니다. 규모가 다르니 혼동하지 마세요.

_사용 예:_

"문서를 붙여 넣으면 API를 정확히 맞히고, 안 붙이면 지어내는 이유가 뭘까요?"

"문서가 들어 있으면 맥락적 지식이에요. 페이지에서 읽는 거죠. 없으면 파라미터 지식이라 드문 엔드포인트가 흐려집니다."
