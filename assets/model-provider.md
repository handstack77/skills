# 모델 제공자 (Model provider)

> 모델

추론을 위해 모델을 서비스하는 주체. 보통 원격(Anthropic, OpenAI, Google)이지만 로컬(Ollama, llama.cpp)일 수도 있습니다.

[추론](./inference.md)을 위해 [모델](./model.md)을 서비스하는 주체입니다. 보통 원격 서비스(Anthropic, OpenAI, Google)이지만, 자기 컴퓨터에서 도는 Ollama, LM Studio, llama.cpp처럼 로컬일 수도 있습니다. [하니스](./harness.md)는 모델을 직접 실행하지 않고 제공자에게 실행해 달라고 요청합니다.

제공자가 기계 장치를 소유합니다. [파라미터](./parameters.md)는 제공자의 하드웨어에 있고, 모든 [모델 제공자 요청](./model-provider-request.md)은 하니스가 네트워크로 [토큰](./token.md)을 보내고 예측을 돌려받는 것입니다. 그래서 모델이나 하니스의 탓으로 잘못 돌려지는 문제의 한 범주 전체가 제공자에서 나옵니다. 속도 제한, 용량 저하, 장애가 모두 여기에 있습니다. [에이전트](./agent.md)가 [세션](./session.md) 도중 멈추거나 모든 [턴](./turn.md)에서 오류가 나면 무엇보다 먼저 제공자의 상태 페이지를 확인해 볼 만합니다.

제공자는 상업적 조건도 정합니다. [입력](./input-tokens.md)과 [출력 토큰](./output-tokens.md)의 토큰당 가격, [프리픽스 캐시](./prefix-cache.md) 할인, 어떤 모델을 쓸 수 있는가. 제공자와 모델을 만든 곳이 다른 회사일 수 있다는 점에 유의하세요. Bedrock, Vertex, OpenRouter는 다른 곳의 모델을 서비스합니다.

로컬 제공자는 성능을 주고 통제권을 얻습니다. 자기 하드웨어에 들어가는 모델은 최전선 모델보다 훨씬 작지만, 아무것도 기계 밖으로 나가지 않고 토큰당 청구서도 없습니다.

_사용 예:_

"망 분리된 고객사용으로 이걸 오프라인에서 돌릴 수 있을까요?"

"모델 제공자를 로컬로 바꾸세요. 그쪽 장비의 Ollama나 llama.cpp로요. 하니스는 신경 쓰지 않아요. 다른 엔드포인트를 칠 뿐입니다."
