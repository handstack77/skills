# 프로토타이핑 (Prototyping)

> 작업 패턴

대화로는 충실도가 너무 낮아서 이야기할 실물이 필요할 때, 에이전트에게 빠르고 거친 버전을 만들게 하는 것.

대화로는 충실도가 너무 낮아서 이야기할 실물이 필요할 때, [에이전트](./agent.md)에게 무언가의 빠르고 거친 버전을 만들게 하는 것입니다.

[집요하게 질문하기](./grilling.md)는 설계 결정을 대화로 풉니다. 대화는 싸지만 충실도가 낮습니다. 어떤 질문은 말로 답할 수 없습니다. 상호작용이 어떤 느낌인지, API 모양이 실제 호출 코드에서 쓰기 편한지, 레이아웃이 실제 데이터 크기에서 작동하는지 같은 것입니다. 인터뷰가 그런 질문에 닿으면 정직한 답은 "모르겠어요, 봐야 알겠어요"입니다. 그 지점을 넘으면 논의는 맴돕니다. 대신 에이전트가 그것을 만들게 하고, 보고, 답을 가지고 대화로 돌아오세요.

에이전트가 만드는 비용을 낮추었기에 이것이 실용적입니다. 예전에는 목업에 하루가 걸리던 거친 버전이 이제 몇 분이면 되므로 일상적으로 해 볼 만합니다. [사람이 개입하는](./human-in-the-loop.md) 기법입니다. 프로토타입은 당신이 반응하라고 있는 것입니다.

보통 한 번 보고 끝내지 않습니다. 프로토타입과 반복합니다. 반응하고, 변경을 요청하고, 다시 반응하며, 라운드마다 실제 산출물을 놓고 대화가 허용하는 것보다 높은 충실도로 또 하나의 결정을 풉니다.

프로토타입이 전부 엉성할 필요는 없습니다. 실제로 평가하는 부분만 프로덕션 품질로 만들 수 있고, 그러면 결정이 내려졌을 때 당신이 반응한 컴포넌트나 API를 실제 코드베이스로 옮길 수 있습니다. 그래서 프로토타이핑은 [명세](./spec.md)가 참조할 필수 자료가 됩니다.

_사용 예:_

"마법사 UI를 한 페이지로 할지 세 단계로 할지로 30분을 논쟁했어요."

"말로는 결론이 안 나요. 에이전트에게 둘 다 프로토타입으로 만들게 하세요. 클릭해 보면 5분 안에 알 수 있습니다."
