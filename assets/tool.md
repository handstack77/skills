# 도구 (Tool)

> 도구와 환경

에이전트가 호출하도록 하니스가 노출하는 함수. Read, Write, Bash, Search 같은 것입니다.

[에이전트](./agent.md)가 호출하도록 [하니스](./harness.md)가 노출하는 함수입니다. Read, Write, Bash, Search 같은 것입니다. 도구는 에이전트가 [환경](./environment.md)을 인지하고 그 위에서 행동하는 방법입니다. [도구 결과](./tool-result.md)를 통하지 않고는 환경을 볼 수 없고, [도구 호출](./tool-call.md)을 통하지 않고는 환경을 바꿀 수 없습니다. 결과가 모델에게 돌아가야 다음에 무엇을 할지 정할 수 있으므로, 도구 호출마다 [모델 제공자 요청](./model-provider-request.md)이 한 번씩 더 듭니다.

대부분의 코딩 에이전트가 기본 제공하는 도구:

| 도구 | 하는 일 |
| --- | --- |
| Read | 파일 내용을 도구 결과로 돌려줍니다 |
| Write | [파일 시스템](./filesystem.md)에서 파일을 만들거나 편집합니다 |
| Bash | 셸 명령을 실행하고 출력을 돌려줍니다 |
| Search | 코드베이스 전체에서 패턴에 맞는 파일이나 텍스트를 찾습니다 |

도구는 세 가지로 정의됩니다. 이름, 하는 일에 대한 설명, 파라미터 스키마입니다. 하니스는 이 정의를 요청마다 [모델](./model.md)에 보내고, 모델은 다른 모든 것을 만드는 것과 같은 방식으로 도구를 고릅니다. [토큰](./token.md)을 써서, 이 경우에는 인자가 달린 구조화된 호출을 씁니다. 모델은 직접 아무것도 실행하지 않습니다. 하니스가 호출을 읽고, 함수를 실행하고, 결과를 돌려보냅니다.

도구 목록이 에이전트가 할 수 있는 일을 정합니다. 유능한 모델도 도구 집합이 좁으면 좁은 에이전트입니다. 가진 것으로 모든 것을 해결하려 들며, 에이전트가 Bash에 그토록 크게 의존하는 이유가 이것입니다. 셸은 시스템 대부분에 닿는 도구 하나입니다. 에이전트에게 능력을 깔끔하게 주려면 그것을 위한 도구를 추가하세요. [MCP](./mcp.md)는 하니스 바깥의 도구를 꽂는 표준입니다.

도구 정의는 요청마다 [컨텍스트](./context.md)를 차지하므로, 큰 도구 집합은 도구를 하나도 호출하기 전부터 상시 비용이 들고, 비슷하게 설명된 도구가 많으면 모델이 올바른 도구를 고르는 능력도 떨어집니다.

_사용 예:_

"에이전트가 스테이징을 직접 조회할 수 있나요?"

"하니스에 스테이징에서 읽기 전용으로 제한한 `psql` 도구를 추가하세요. 도구가 없으면 에이전트는 파일 시스템 밖의 것은 전혀 보지 못합니다."
