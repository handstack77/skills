# 입력 토큰 (Input tokens)

> 모델

하니스가 모델 제공자 요청마다 보내는 토큰. 출력 토큰보다 낮은 요율로 과금됩니다.

[하니스](./harness.md)가 [모델 제공자 요청](./model-provider-request.md)마다 보내는 [토큰](./token.md)으로, [시스템 프롬프트](./system-prompt.md), 대화 이력, [도구 결과](./tool-result.md) 등 [모델](./model.md)이 쓰기 전에 읽는 모든 것입니다. 처리하는 비용이 [출력 토큰](./output-tokens.md)보다 적게 들기 때문에 더 낮은 요율로 과금됩니다.

[AI](./ai.md) 코딩을 할 때 청구서의 대부분은 입력 토큰입니다. 모델은 [상태가 없으므로](./stateless.md) 매 [턴](./turn.md)이 [세션](./session.md) 전체를 입력으로 다시 보냅니다. 첫 메시지, 모든 응답, 그 뒤의 모든 도구 결과. 50번째 턴의 입력에는 앞선 49개 턴이 들어 있습니다. 모델 제공자 요청 하나가 출력 토큰은 몇백 개만 만들면서 누적된 이력 십만 입력 토큰을 다시 보낼 수 있습니다.

[프리픽스 캐시](./prefix-cache.md)가 비용을 줄입니다. 이전 요청과 정확히 일치하는 이력은 정가 입력이 아니라 저렴한 [캐시 토큰](./cache-tokens.md)으로 과금됩니다. 그래도 입력 비용이 부담스럽다면 해법은 다시 보내지는 양을 줄이는 것입니다. 작업 사이에 [비우거나](./clearing.md) [압축](./compaction.md)하세요.

_사용 예:_

"청구서는 높은데 [에이전트](./agent.md)는 거의 쓰는 게 없어요."

"입력 토큰이에요. 매 턴마다 세션 전체를 다시 보내거든요. 프리픽스 캐시가 없으면 요청마다 이력 값을 다시 냅니다."
