# 시스템 프롬프트 (System prompt)

> 세션, 컨텍스트 창, 턴

하니스가 모든 모델 제공자 요청 앞에 붙이는 지침. 에이전트의 상시 브리핑입니다. 보통 세션 내내 안정적입니다.

[하니스](./harness.md)가 모든 [모델 제공자 요청](./model-provider-request.md) 앞에 붙이는 지침으로, [에이전트](./agent.md)의 상시 브리핑입니다. 자신이 누구인지, 어떻게 행동할지, 어떤 [도구](./tool.md)를 호출할 수 있는지, 어떤 관례를 따를지. 보통 [세션](./session.md) 내내 안정적입니다.

시스템 프롬프트는 당신이 아니라 하니스 벤더가 쓰며, 코딩 하니스에서는 큽니다. 행동 규칙, 도구 설명, 엣지 케이스 처리가 흔히 수만 [토큰](./token.md)에 달하고, 모두 매 [턴](./turn.md)마다 [입력 토큰](./input-tokens.md)으로 비용이 듭니다. 당신의 상시 지침도 함께 실립니다. [AGENTS.md](./agents-md.md) 같은 파일이 세션 시작 때 시스템 프롬프트 옆에 로드되므로, [모델](./model.md)은 당신의 메시지를 보기도 전에 벤더의 브리핑과 당신의 브리핑을 함께 읽습니다.

모든 요청에서 동일하므로 [프리픽스 캐시](./prefix-cache.md)의 시작 부분을 이룹니다. 하니스가 진행하면서 고치지 않고 세션 내내 고정하는 이유의 일부입니다.

모델은 사용자 메시지보다 시스템 프롬프트를 우선하도록 학습됩니다. 그래서 에이전트가 요청한 적 없는 관례를 고집하거나 떨쳐 낼 수 없는 방식으로 출력을 서식화한다면, 보통 시스템 프롬프트에 복종하는 것이고 당신의 메시지가 논쟁에서 지고 있는 것입니다. 일부 하니스는 커스터마이즈할 수 있습니다. 시스템 프롬프트에 대한 전체 접근을 주므로, 에이전트가 실제로 듣고 있는 것을 읽고 바꿀 수 있습니다.

_사용 예:_

"하니스 둘이 같은 모델인데 같은 프롬프트에 완전히 다르게 동작해요."

"시스템 프롬프트가 달라서예요. 하나는 간결한 코드 편집에, 다른 하나는 설명에 맞춰져 있어요. 차이는 당신의 메시지가 도착하기도 전에 거기서 생깁니다."
