# 주의 관계 (Attention relationship)

> 실패 모드

두 토큰 사이의 짝. 의미 있는 짝은 무관한 짝보다 서로 더 큰 영향을 줍니다. 토큰 N개의 컨텍스트에는 대략 N²개의 짝이 있습니다.

각 [토큰](./token.md)을 예측할 때 [모델](./model.md)은 [컨텍스트](./context.md)의 다른 모든 토큰을 고려합니다. 어떤 것은 크게, 어떤 것은 거의 전혀 반영하지 않습니다. 두 토큰 사이의 짝이 **주의 관계(attention relationship)**이며, 의미 있는 짝("her"와 "Sarah", 또는 `getUser()` 호출과 `function getUser` 정의)은 무관한 짝보다 서로 더 큰 영향을 줍니다. 토큰 N개의 컨텍스트에는 N² 정도의 관계가 있습니다.

모델의 겉보기 이해가 사는 곳이 이 짝들입니다. 대명사를 풀 때는 "her"와 "Sarah" 사이의 주의 관계가 강하기 때문입니다. 올바른 인자로 함수를 호출할 때는 호출 지점과 앞서 읽은 정의 사이의 관계가 일을 하고 있습니다. 이 중 어느 것도 조회되지 않습니다. 모든 [모델 제공자 요청](./model-provider-request.md)에서 모든 쌍에 대해 새로 계산됩니다.

N²라는 수치는 곱씹어 볼 만합니다. 직관이 말하는 것보다 빠르게 커지기 때문입니다.

| 컨텍스트 크기 | 짝의 수(~N²) |
| --- | --- |
| 1,000 토큰 | 약 100만 |
| 10,000 토큰 | 약 1억 |
| 100,000 토큰 | 약 100억 |

각 짝은 또 한 번 이상 계산됩니다. 모델에는 여러 어텐션 헤드가 있으며(최전선 모델의 정확한 수는 공개되지 않았지만 50~100개가 합리적인 추정입니다), 각 헤드가 모든 관계의 자기 버전을 계산합니다. 그러니 위 표의 모든 짝이 모든 헤드에 걸쳐 중복됩니다. 아주 많은 짝입니다.

어떤 작업에든 중요한 관계는 그중 아주 일부입니다. 당신의 지침과 그것이 다스리는 코드 사이의 짝은 의미 있는 몇 안 되는 것 중 하나이고, 풀의 나머지는 거의 전부 잡음입니다. 둘은 다른 속도로 늡니다. 중요한 관계는 대체로 일정한데 전체 풀은 컨텍스트 크기에 따라 제곱으로 커집니다. 1,000 토큰에서는 신경 쓰는 짝이 100만 분의 1이고, 100,000 토큰에서는 100억 분의 1입니다. 이것이 [주의 예산](./attention-budget.md) 밑에 깔린 산수이며, [주의 저하](./attention-degradation.md)는 중요한 관계가 너무 얇은 몫만 받을 때 느껴지는 모습입니다.

_사용 예:_

"diff 전체에서 두 `user` 심볼을 계속 혼동해요. [바보 구간](./smart-zone.md)에 들어선 것 같네요."

"네, 각 호출 지점과 선언 사이의 주의 관계가 다른 쪽과 싸우고 있어요. 토큰 모양은 같은데 바인딩이 다르니까요. 하나의 이름을 바꾸면 짝이 선명해집니다."
