# 하니스 (Harness)

> 모델

모델을 에이전트로 만드는 모델 주변의 모든 것: 도구, 시스템 프롬프트, 컨텍스트 창 관리, 권한, 훅.

[모델](./model.md)을 [에이전트](./agent.md)로 만드는 모델 주변의 모든 것입니다. [도구](./tool.md), [시스템 프롬프트](./system-prompt.md), [컨텍스트 창 관리](./context-window.md), 권한, 훅. 이 저장소에서는 **Claude Code**와 **Codex CLI**의 도구, 권한, 프로젝트 지침을 각각 구분합니다.

모델 자체는 한 가지만 합니다. 텍스트를 받아 텍스트를 내놓습니다. 파일을 읽거나 명령을 실행하거나 지난 [턴](./turn.md)을 기억하지 못합니다. 이 모두를 하니스가 제공합니다. 하니스는 [모델 제공자 요청](./model-provider-request.md)마다 [컨텍스트](./context.md)를 조립하고, 모델이 요청한 [도구 호출](./tool-call.md)을 실행하고, [도구 결과](./tool-result.md)를 다시 넣어 주고, [세션](./session.md) 이력을 저장하고, 위험한 행동 전에 당신에게 권한을 묻고, 언제 [압축](./compaction.md)할지 결정합니다. 모델이 제안하고 하니스가 실행하는 것을 반복하는 에이전트 루프는 하니스가 돌립니다.

이는 원인을 진단할 때 중요합니다. 두 제품 사이, 또는 어제와 오늘 사이에 동작이 다를 때 변수는 모델이 아니라 하니스인 경우가 많습니다. 다른 시스템 프롬프트, 다른 도구 집합, 바뀐 권한 기본값, 새 컨텍스트 관리 전략은 모두 모델이 바뀌지 않아도 동작을 바꿉니다. 또한 설정 대부분이 하니스에 있다는 뜻이기도 합니다. [AGENTS.md](./agents-md.md) 파일, 권한 설정, 훅은 모두 모델이 아니라 하니스에 주는 지침입니다.

이 저장소에서 다루는 하니스는 Claude Code와 Codex CLI입니다.

_사용 예:_

"같은 스킬을 읽는데 왜 두 CLI에서 파일 접근이나 명령 실행 결과가 다르죠?"

"각 CLI의 [파일 시스템](./filesystem.md) 접근 권한, 사용 가능한 도구와 프로젝트 지침을 확인하세요. 하니스 설정도 실행 결과에 영향을 줍니다."
