# 도구 결과 (Tool result)

> 도구와 환경

하니스가 도구 호출을 실행한 뒤 돌려보내는 것: 파일 내용, 출력, 또는 오류. 에이전트가 환경을 보는 유일한 창입니다.

[하니스](./harness.md)가 [도구 호출](./tool-call.md)을 실행한 뒤 돌려보내는 것으로, 파일 내용, 명령 출력, 오류입니다. [에이전트](./agent.md)가 [환경](./environment.md)을 보는 유일한 창입니다. _다음_ [모델 제공자 요청](./model-provider-request.md)에 실려 [모델](./model.md)에게 돌아가고, 모델은 거기서 그것으로 무엇을 할지 정합니다. 도구 호출과 도구 결과는 한 교환의 양 끝이며, 둘 다 한 [턴](./turn.md) 안에 있습니다.

도구 결과의 수명 주기:

| 단계 | 주체 | 일어나는 일 |
| --- | --- | --- |
| 1 | 하니스 | 도구 호출을 실행: 명령을 실행하거나 파일을 읽음 |
| 2 | 하니스 | 결과를 포착: 출력, 내용, 또는 오류 |
| 3 | 하니스 | 그것을 메시지로 [컨텍스트](./context.md)에 덧붙임 |
| 4 | 하니스 | 다음 모델 제공자 요청에서 전체 컨텍스트를 제공자에게 보냄 |
| 5 | 모델 | 결과를 읽고 결정: 또 다른 도구 호출, 또는 최종 답변 |

결과는 [세션](./session.md)의 나머지 동안 컨텍스트에 남습니다. 도구 결과는 보통 코딩 세션 컨텍스트의 대부분입니다. 읽은 모든 파일, 실행한 모든 테스트, 모든 검색이 통째로 들어와 쓸모가 없어진 뒤에도 오래도록 [토큰](./token.md)을 차지합니다. 장황한 테스트 로그나 통째로 읽은 생성 파일 같은 큰 결과 몇 개가 대화 자체보다 더 빠르게 세션을 [컨텍스트 창](./context-window.md)의 가장자리로 밀어붙일 수 있습니다.

결과가 모델이 보는 전부이므로, 모델은 그 뒤의 환경을 확인할 방법이 없습니다. 출력이 잘렸거나, 명령이 조용히 실패했거나, 하니스가 내용 대신 오류를 돌려주었다면 모델은 주어진 것으로 추론합니다. 에이전트가 가진 시스템의 그림이 틀려 보일 때는 도구 결과를 보세요. 기록 어딘가에 당신이 아는 사실과 다른 것을 말하는 결과가 있습니다.

_사용 예:_

"파일이 비어 있는 것처럼 추론하고 있어요."

"도구 결과가 내용이 아니라 권한 거부로 돌아왔어요. 모델은 오류 문자열만 봤고 파일을 볼 다른 방법이 없습니다."
