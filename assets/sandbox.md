# 샌드박스 (Sandbox)

> 도구와 환경

에이전트가 그 안에서 실행되는 격리된 환경. 컨테이너, VM, 또는 제한된 셸. 에이전트 행동의 피해 반경을 제한합니다.

[에이전트](./agent.md)가 그 안에서 실행되는 격리된 [환경](./environment.md)입니다. 컨테이너, VM, 일회용 [파일 시스템](./filesystem.md), 또는 권한이 제한된 셸. 에이전트 행동의 피해 반경을 제한합니다. 에이전트가 파괴적인 명령을 실행하거나 악성 무언가를 가져오더라도 피해는 억제됩니다. [AFK](./afk.md)를 실용적으로 만드는 안전의 토대입니다.

샌드박스와 [권한 모드](./permission-mode.md)는 같은 문제를 반대쪽 끝에서 풉니다. 권한은 행동이 실행되기 전에 묻고, 샌드박스는 행동이 실행되더라도 닿을 수 있는 범위를 제한합니다. 권한은 당신이 [루프 안에](./human-in-the-loop.md) 있어야 하며 모든 프롬프트가 방해이므로, 끊임없이 묻는 세션은 자율적이라고 하기 어렵습니다. 샌드박스는 주의 대신 인프라를 씁니다. 격리가 강할수록 물어야 할 질문이 줄어듭니다.

격리에는 등급이 있습니다.

| 등급 | 무엇인가 | 무엇을 가두나 |
| --- | --- | --- |
| 제한된 셸 | 명령마다 OS 수준으로 가두기 | 프로젝트 밖의 쓰기, 네트워크 접근 |
| 컨테이너 | 새 파일 시스템, 마운트된 자격 증명 없음, 끝나면 폐기 | 에이전트가 자기 머신에 하는 모든 것 |
| VM / 클라우드 | 완전히 별개의 머신, 흔히 하니스가 제공 | 커널 수준 탈출을 포함한 모든 것 |

어떤 샌드박스도 가두지 못하는 것은 정당하게 샌드박스를 떠나는 행동입니다. 당신의 git 자격 증명을 가진 에이전트는 푸시할 수 있고, 네트워크 접근이 있는 에이전트는 프로덕션 API를 호출할 수 있습니다. 경계를 얼마나 두껍게 할지 정하기 전에 무엇이 경계를 넘을지 먼저 정하세요.

_사용 예:_

"밤새 [권한 우회](./agent-mode.md)로 돌리게 하고 싶은데 아직 마음의 준비가 안 됐어요."

"샌드박스에 넣으세요. 새 컨테이너에 자격 증명을 마운트하지 않고 외부 네트워크도 없게요. 최악의 경우 자기 파일 시스템을 날리고, 당신은 컨테이너를 폐기하면 됩니다."
