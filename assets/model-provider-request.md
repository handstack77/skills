# 모델 제공자 요청 (Model provider request)

> 모델

하니스에서 모델 제공자로 가는 한 번의 왕복. 하니스가 컨텍스트를 보내면 제공자가 응답 하나를 돌려줍니다.

[하니스](./harness.md)에서 [모델 제공자](./model-provider.md)로 가는 한 번의 왕복입니다. 하니스가 현재 [컨텍스트](./context.md)를 보내면 제공자가 응답 하나([도구 호출](./tool-call.md) 또는 최종 답변)를 돌려줍니다. [에이전트](./agent.md)가 [도구](./tool.md)를 호출하면 사용자 메시지 하나가 여러 모델 제공자 요청을 낳을 수 있습니다. 각 [도구 결과](./tool-result.md)가 또 다른 요청을 촉발하기 때문입니다.

요청마다 모든 것을 싣습니다. [시스템 프롬프트](./system-prompt.md), 지금까지의 전체 대화, 모든 도구 결과. [모델](./model.md)은 [상태가 없으므로](./stateless.md) 제공자는 요청 사이에 아무것도 보관하지 않습니다. 40번째 요청은 39번째가 보낸 것에 도구 결과 하나를 더해 다시 보냅니다. [프리픽스 캐시](./prefix-cache.md)는 이 반복을 감당할 만하게 만들려고 존재합니다.

요청은 과금의 단위이기도 합니다. [입력 토큰](./input-tokens.md), [출력 토큰](./output-tokens.md), 캐시 할인이 모두 요청마다 계산되므로, 무해해 보이는 질문이 놀랄 만큼 비쌀 수 있습니다. 비용은 당신의 메시지에 비례하는 것이 아니라 요청 수에 요청마다 실린 컨텍스트의 크기를 곱한 것에 비례합니다.

요청을 [턴](./turn.md)과 구분해 두는 것이 좋습니다. 턴은 당신과의 한 번의 교환이고, "실패하는 테스트를 고쳐" 같은 하나의 턴이 요청의 사슬로 펼쳐집니다.

| 요청 | 모델이 돌려주는 것 | 이후 하니스가 하는 일 |
| --- | --- | --- |
| 1 | 도구 호출: 테스트 실행 | 실행하고 실패 출력을 덧붙임 |
| 2 | 도구 호출: 테스트 파일 읽기 | 파일 내용을 덧붙임 |
| 3 | 도구 호출: 소스 파일 읽기 | 파일 내용을 덧붙임 |
| 4 | 도구 호출: 소스 파일 편집 | 편집을 적용하고 결과를 덧붙임 |
| 5 | 도구 호출: 테스트 다시 실행 | 실행하고 통과 출력을 덧붙임 |
| 6 | 최종 답변: "고쳤고 테스트 통과" | 당신에게 보여 줌 |

한 턴에 요청 여섯 번이고, 각각이 전체 컨텍스트를 다시 보냅니다. [토큰](./token.md)이 어디로 갔는지 궁금하면 턴이 아니라 요청을 세어 보세요.

_사용 예:_

"질문 하나가 토큰 4만 개를 태웠다고요?"

"도구 호출을 보세요. grep 열두 번, 읽기 여덟 번, 편집 네 번이에요. 각 도구 결과가 또 다른 모델 제공자 요청을 낳고, [세션](./session.md) 전체 프리픽스가 매번 다시 전송됩니다."
