# AGENTS.md

> 기억과 조향

하니스가 세션 시작 시 컨텍스트 창에 로드하는 환경 속 파일. 에이전트에게 주는 프로젝트의 상시 브리핑.

[하니스](./harness.md)가 [세션](./session.md) 시작 시 [컨텍스트 창](./context-window.md)에 로드하는 [환경](./environment.md) 속 파일로, [에이전트](./agent.md)에게 주는 프로젝트의 상시 브리핑입니다. 하니스를 넘나드는 관례이며, 일부 하니스는 자체 변형을 갖고 있습니다(Claude Code는 CLAUDE.md).

자동으로 로드되므로 세션마다 같은 말을 반복하지 않는 한 방법입니다. [모델](./model.md)은 [상태가 없어서](./stateless.md) 한 세션에서 한 교정이 다음 세션에서는 사라지고, 새 세션마다 프로젝트가 pnpm을 쓴다거나, 테스트를 특정 플래그로 돌린다거나, 어떤 디렉터리는 생성물이라 건드리면 안 된다고 알려 주게 됩니다. 같은 일로 에이전트를 두 번 교정했다면 그 교정은 AGENTS.md에 넣을 후보 줄입니다.

적합한 내용은 코드에서 에이전트가 알아낼 수 없는 것입니다. 빌드와 테스트 명령, 코드베이스에서 분명하지 않은 관례, 엄격한 제약("생성된 클라이언트는 절대 편집하지 말 것") 등입니다. 짧고 단정적으로 씁니다. 문서가 아니라 브리핑입니다.

단점은 안에 든 모든 것이 항상 로드된다는 점입니다. 지침이 쌓이면 대부분은 어떤 작업에도 무관하고, 긴 AGENTS.md는 토큰을 쓰는 데다 스스로를 희석합니다. 컨텍스트에 지침이 많을수록 모델이 그중 하나를 지키는 정도가 떨어집니다.

_피할 표현:_ [점진적으로 공개](./progressive-disclosure.md)해야 할 내용을 AGENTS.md에 넣는 것. 거기 있는 모든 것은 해당 세션에 필요하든 아니든 모든 세션의 모든 [턴](./turn.md)마다 [토큰](./token.md) 비용을 치릅니다. 스타일 가이드는 대신 [스킬](./skill.md)이나 [컨텍스트 포인터](./context-pointer.md) 뒤에 둘 수 있습니다. AGENTS.md는 어디에나 적용되는 줄만 남깁니다.

_사용 예:_

"왜 모든 세션이 시작부터 4k 토큰을 쓰고 있죠?"

"AGENTS.md를 확인해 보세요. 누가 스타일 가이드 전체를 스킬 뒤에 두지 않고 거기에 붙여 넣었어요."
