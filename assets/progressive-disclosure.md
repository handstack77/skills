# 점진적 공개 (Progressive disclosure)

> 기억과 조향

에이전트가 지금 필요한 컨텍스트만 로드하고 나머지는 컨텍스트 포인터로 가리키는 것. UI 설계에서 빌려 왔습니다.

[에이전트](./agent.md)가 지금 필요한 [컨텍스트](./context.md)만 로드하고 나머지는 [컨텍스트 포인터](./context-pointer.md)로 가리키는 것입니다. UI 설계에서 빌려 온 말로, 거기서는 사용자에게 현재 작업과 관련된 컨트롤만 보여 주고 나머지는 클릭 뒤에 숨기는 것을 뜻합니다.

이 기법이 있는 이유는 컨텍스트가 두 번 비용이기 때문입니다. 미리 로드한 모든 [토큰](./token.md)은 매 [턴](./turn.md)마다 [입력 토큰](./input-tokens.md)으로 과금되고, 에이전트가 필요로 하든 아니든 모든 토큰이 [주의 예산](./attention-budget.md)을 씁니다. 스타일 가이드 전체, 배포 런북, 데이터베이스 관례를 가득 채운 [AGENTS.md](./agents-md.md)는 에이전트를 그 모든 것에서 더 못하게 만듭니다. 현재 작업에 중요한 지침이 그렇지 않은 지침에 희석됩니다. 징후는 컨텍스트에 있다고 알고 있는 규칙을 에이전트가 무시하는 것입니다. 들어 있지만 묻혀 있는 것입니다.

점진적 공개는 이를 뒤집습니다. 항상 로드되는 계층은 작게 유지합니다. 주제당 한 문장과 세부 정보가 있는 곳을 가리키는 포인터입니다. 에이전트는 컴포넌트를 쓸 때 스타일 가이드를 읽고, 배포할 때 배포 런북을 읽고, 테스트를 고칠 때는 둘 다 읽지 않습니다. [스킬](./skill.md)은 [하니스](./harness.md)에 내장된 이 패턴입니다. 짧은 설명은 매 [세션](./session.md)마다 로드되고, 전체 지침은 발동될 때만 로드됩니다.

_사용 예:_

"스타일 가이드 전체를 AGENTS.md에 넣어도 될까요?"

"아니요, 점진적 공개로 가세요. 스타일 가이드를 에이전트가 컴포넌트를 실제로 쓸 때 로드하는 스킬로 참조하세요. AGENTS.md는 매 턴마다 토큰 비용을 치릅니다."
