## 하는 일

`wizard`는 사람에게 수동 절차를 단계별로 안내하는 대화형 bash 스크립트를 생성합니다. 서드파티 서비스 연결, 일회성 마이그레이션, 프로젝트를 상태 A에서 B로 옮기기 같은 것입니다. 각 URL을 열고, 무엇을 클릭하고 복사할지 말하고, 돌아오는 것을 캡처하고, `.env` 파일과 GitHub Actions 시크릿에 씁니다.

[에이전트](../../assets/agent.md)는 스크립트를 쓰되 절대 실행하지 않습니다. 당신이 자기 머신에서 실행합니다. 마법사는 지시 목록이 아니라 프로그램입니다. 스크립트가 각 단계를 순서대로 실행하고 입력한 값을 보관합니다. 당신의 몫은 클릭하고, 붙여 넣고, Enter를 누르는 것입니다.

## 언제 쓰나

`/wizard`를 입력할 수 있고, 에이전트가 스스로 꺼낼 수도 있습니다. 당신이 밟아야 하는 단계(발급할 수 없는 키, 클릭할 수 없는 대시보드)에 부딪히면, 지시를 스크롤되어 사라지는 채팅에 쓰는 대신 마법사를 만들어 줍니다.

다음에 당신을 막는 것이 대시보드 방문일 때 쓰세요.

| 상황 | 마법사가 하는 일 |
| --- | --- |
| 새 개발자가 앱이 부팅되기 전에 서비스 여섯 개를 설정해야 함 | 각 대시보드를 순서대로 열고, 키를 캡처하고, `.env`와 CI에 씀 |
| 일회성 마이그레이션이 특정 순서로 스위치를 뒤집어야 함 | 되돌릴 수 없는 단계를 확인 게이트 뒤에 순서대로 배치 |
| 프로젝트를 한 번 상태 A에서 B로 옮겨야 함 | 전환을 안내하고 하지 못한 것을 보고 |
| 그 단계들을 README에 쓰려는 중 | 대신 실행 가능한 버전을 쓰며, 단계가 낡으면 눈에 띄게 실패함 |

무엇을 만들지 *결정*하는 데는 쓰지 마세요. 그것에는 [grill-with-docs](../../assets/skills-grill-with-docs.md)와 [to-spec](../../assets/skills-to-spec.md)이 도구입니다.

## 선행 조건

생성하는 데 필요한 것은 없습니다. 쓰이는 마법사는 bash에서 실행되며, 스테이지가 GitHub 시크릿이나 변수를 설정할 때 `gh`를 씁니다. `gh`가 없거나 인증되지 않았다면 실행이 실패하지 않습니다. 그 스테이지가 경고를 표시하고, 마무리 요약이 직접 설정할 것을 알려 줍니다.

## 스테이지

**스테이지**는 한 화면의 집중된 작업 하나입니다. 스크립트가 스테이지 사이에 터미널을 지우므로, 화면을 넘치는 스테이지는 스크롤되어 사라진 부분을 잃습니다. 스테이지는 의존성 순서로 작성하고 진행 표시를 구동하는 `TOTAL_STAGES`를 설정합니다.

[스킬](../../assets/skill.md)은 스크립트를 쓰기 전에 절차의 범위를 정합니다. 불쑥 묻지 않고 저장소를 읽습니다. `.env*`, `docker-compose*`, 프레임워크 설정, `.github/workflows/`의 모든 `secrets.*` / `vars.*` 참조입니다. 그 참조 하나하나가 마법사가 만들어 내야 하는 값입니다. 그다음 순서가 있는 스테이지 목록을 보여 주고 확인받습니다. 당신이 확인한 뒤에야 각 스테이지를 사람이 따라갈 정확한 경로("Dashboard → Developers → API keys → Reveal test key → 복사")에 매핑합니다. 현재 UI를 모르는 곳에서는 클릭을 지어내지 않고 당신에게 묻거나 문서를 확인합니다.

캡처하는 각 값에 대해 범위 정하기가 그것이 갈 곳을 정합니다.

| 목적지 | 이럴 때 |
| --- | --- |
| `.env`만 | 로컬 개발에 필요하고 CI는 필요 없음 |
| GitHub 시크릿 | CI가 읽고, 민감함 |
| GitHub 변수 | CI가 읽고, 공개임 |
| `.env`와 시크릿 둘 다 | 로컬 개발과 CI가 모두 필요 |
| 어디에도 없음 | 스테이지가 순수한 동작: 스위치를 뒤집음, 플랜을 업그레이드함 |

## 템플릿이 이미 UX를 해결했습니다

템플릿이 경험 전체를 제공합니다. 남은 시간이 있는 진행 상황, 확인 게이트, WSL을 포함한 크로스 플랫폼 URL 열기, 시크릿의 숨겨진 입력, 멱등적인 `.env` upsert, `gh secret` / `gh variable` 쓰기, 건너뛰어야 했던 모든 것의 마무리 요약. `STAGES` 표식 위의 모든 것은 모든 마법사에서 동일하고 손으로 고치지 않는 고정 라이브러리입니다. 라이브러리가 바뀌지 않으므로 모든 마법사가 같은 방식으로 동작합니다. 마법사마다 할 일은 절차의 범위를 정하고 그 스테이지를 작성하는 것뿐입니다.

마법사를 쓰는 에이전트는 끝까지 실행하지 않습니다. 스크립트가 브라우저를 열고 사람의 입력을 기다리기 때문입니다. 대신 정적으로 확인합니다. `bash -n`, 가능하면 `shellcheck`, 그리고 모든 값이 범위 정하기가 말한 곳에 착지하고 모든 `set_secret` 이름이 CI의 실제 `secrets.*` 참조와 일치하는지 추적하는 것. 그러므로 첫 실행은 당신의 것이고, 그 실행이 테스트입니다.

## 기본적으로 일회용

| 가진 것 | 스크립트로 할 일 |
| --- | --- |
| 일회성 마이그레이션, 개인 설정, 다시 하지 않을 전환 | 임시 경로나 `scripts/` 경로에 저장하고, 실행하고, 삭제 |
| 저장소의 다음 사람도 필요로 할 설정 경로 | 커밋하고 README에서 링크해서, 에이전트에게 다시 묻지 않고 스크립트를 실행하게 함 |

## 자주 묻는 질문

**제 API 키가 모델의 컨텍스트에 들어가나요?**

아니요. 에이전트는 스크립트를 쓰고 실행하지 않습니다. 당신이 스크립트를 직접 실행하고, 스크립트는 숨겨진 터미널 입력으로 키를 캡처해 `.env`나 `gh secret`에 곧바로 씁니다. 마법사는 CLI이고 모델은 거기에 연결되어 있지 않습니다. 이는 마법사가 실행 중에 캡처하는 값에만 성립합니다. 절차의 범위를 정하는 동안 키를 채팅에 붙여 넣으면, 다른 붙여 넣은 텍스트와 마찬가지로 [컨텍스트](../../assets/context.md)에 들어갑니다.

**잘못 입력한 값을 되돌아가서 고칠 수 있나요?**

실행 도중에는 안 됩니다. 뒤로 가기 버튼이 없습니다. 스테이지는 앞으로 실행되고, 3단계에서 잘못 답했다면 Ctrl-C 후 다시 실행해야 합니다. 이미 `.env`에 쓴 값이 기본값으로 다시 제안되므로 다시 실행하는 비용이 쌉니다. 맞게 한 스테이지는 Enter로 넘기고 틀린 것만 다시 입력하세요. 사용자들이 출시 주간에 이를 요청했고 아직 열려 있습니다. "좋아요! 하나만요, 입력한 것을 되돌아가서 고칠 방법이 있나요?"

**제가 이미 설정한 것을 알고 있나요?**

부분적으로, 그리고 출시 당시의 반응이 가정한 것보다 덜합니다. 묻기 전에 저장소를 읽으므로(`.env` 파일, `docker-compose`, 프레임워크 설정, CI의 `secrets.*` 참조) README처럼 처음부터 시작하지 않고 빠진 값으로 범위를 정합니다. 하지 않는 것은 서드파티 서비스를 확인하는 것입니다. `.env`에 키가 있으면 마법사가 그것을 다시 제안하고 Enter로 유지됩니다. Stripe 계정은 만들었는데 키를 저장하지 않았다면, 마법사는 여전히 그것을 가져오러 대시보드로 보냅니다.

**워크플로의 어디에 위치하나요? 집요한 질문과 명세 뒤인가요?**

특별히 어디도 아닙니다. 체인의 한 단계가 아니라 독립형입니다. 흔한 추측은 `/grill-with-docs → /to-spec → /wizard`이고 그 순서도 괜찮지만, 트리거는 수동 절차가 나타나는 것이며 시작하기 전, 빌드 도중, 출시 한참 뒤 어느 때나 일어날 수 있습니다. 탐색 도구로도 동작합니다. 범위 정하기가 작업에 착수하기 전에 생각하지 못한 API 키 셋 같은 숨은 전제 조건을 찾아냅니다.

**Claude Code와 Codex CLI에서 어떻게 실행하나요?**

Claude Code에서는 `/wizard`, Codex CLI에서는 `$wizard`를 입력하거나 필요한 설정 작업을 설명하세요. 생성되는 마법사는 bash 스크립트이므로 Windows에서는 Git Bash나 WSL 등 bash 실행 환경이 필요합니다. 스킬은 [로컬 설정 안내](../../.agents/install-block.md)에 따라 두 CLI에 연결합니다.

**전에는 사용자 호출형이 아니었나요?**

그랬습니다. 이제는 모델 호출형이어서, 당신이 밟아야 하는 단계에 부딪히면 에이전트가 요청 없이 꺼냅니다. 전에 할 수 있던 것은 하나도 동작을 멈추지 않았습니다. 모델 호출은 당신뿐 아니라 에이전트도 스킬을 호출하게 해 주므로 `/wizard`는 이전처럼 동작합니다. 변경은 한 가지 실패를 고칩니다. 전에는 빌드 도중 자격 증명의 벽에 부딪힌 에이전트가 번호 매긴 여섯 단계를 채팅에 쏟아 내서 손으로 따라 하게 했습니다. 이제는 마법사를 씁니다.

**전에는 `in-progress/`에 있었습니다. 지금은 어디에 있나요?**

`wizard`는 `skills/engineering/wizard`에 있습니다. 기본 플러그인에 포함되므로 [설정 안내](../../.agents/install-block.md)에 따라 설치하고 새 CLI 세션에서 사용하세요.

## 잘 작동하는 신호

- 스크립트가 존재하기 전에 순서 있는 스테이지 목록과 각각이 만드는 값을 보고 확인을 요청받습니다.
- 모든 URL이 그 페이지의 값을 묻기 전에 열립니다. 가져오라고 보내지 않은 것을 붙여 넣으라고 요청받지 않습니다.
- 시크릿은 보이지 않게 입력합니다. 민감한 것이 스크롤백에 에코되지 않습니다.
- 각 스테이지가 한 화면에 들어옵니다. 아직 필요한 것이 스크롤되어 사라지지 않았습니다.
- Ctrl-C 후 다시 실행하면 멈춘 곳에서 이어지며, 이미 저장된 값을 기본값으로 제안합니다.
- 마지막 화면이 쓴 것을 나열하고, 별도로 하지 못해서 직접 마쳐야 하는 것을 나열합니다.

## 전체 흐름에서의 위치

`wizard`는 자동화가 멈추고 사람이 클릭해야 하는 선에 놓인 **언제든 찾는 독립형**입니다. 가장 가까운 이웃은 [setup-me-skills](setup-me-skills.md)입니다. 둘 다 저장소를 동작하는 상태로 만들려고 존재하기 때문입니다. 그것은 이 스킬 모음을 설정하고, `wizard`는 그 밖의 모든 것에 대한 설정 경로를 생성합니다. [implement](../../assets/skills-implement.md)와도 짝을 이룹니다. 빌드가 자격 증명이나 수동 전환이 필요한 기능을 착지시킬 때, 마법사가 사람만 할 수 있는 단계를 맡습니다. 그 순간에 어느 스킬이 맞는지 확신이 없을 때는 [ask-me](../../assets/skills-ask-me.md)가 안내합니다.
