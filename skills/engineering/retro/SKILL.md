> CLI별 스킬 로드: 아래의 `Skill 도구` 지시는 Claude Code에서 해당 도구로 실행합니다. Codex CLI에서는 스킬 이름으로 로컬 `SKILL.md`를 찾아 읽고 같은 절차를 따릅니다. 플러그인 설치에서는 같은 플러그인의 대상 스킬 이름에 `handstack-skills:` 접두사를 붙입니다. 사용자 호출형 스킬은 사용자의 명시적 요청이 있어야 실행합니다.

사용자가 **회고**를 요청했습니다. 앞으로의 실행을 개선하도록 코딩 에이전트의 **환경**에 대한 개선안을 제안하는 것이 당신의 역할입니다.

## 단계

1. Skill 도구로 `writing-for-agents`를 호출해 글쓰기 스타일 가이드를 확인하세요.

2. 사용자가 지정한 세션의 1차 자료를 읽으세요. 이 머신의 세션 로그를 검색해야 할 수도 있습니다. 사용자가 세션을 지정하지 않으면 현재 세션을 기본으로 하세요.

3. 아래 범주에서 개선 후보를 찾으세요.

- **탐색**: 에이전트가 올바른 파일을 찾기가 얼마나 쉬웠나요? 파일 사이에 숨은 의존성이 있나요? **탐색 포인터**가 있으면 더 쉬웠을까요? _사용 시점_: 정보 하나를 찾는 데 세션이 오래 걸렸을 때.
- **자동 검사**: 에이전트가 저지른 오류를 잡아낼 자동 검사가 있을까요? 린트, 타입 검사, 테스트, 파일 시스템 린터 같은 것입니다. 먼저 저장소 자체의 검사 명령(`package.json`이나 빌드 도구의 `lint`/`check` 스크립트, CI 워크플로)을 읽어서, 이미 있지만 연결되지 않았거나 조용히 깨진 검사를 발견 사항으로 삼고 새로 만들지 마세요. **가드레일**이 전혀 없는 저장소(pre-commit 훅도, 린트/타입 검사/테스트 명령을 실행하는 CI 잡도 없음)는 그 자체로 발견 사항입니다. 린트하지 않는 저장소는 중립적인 기본값이 아니라 계속 놓치고 있는 기회입니다. _사용 시점_: 자동 검사로 잡을 수 있었던 실수를 에이전트가 했거나, 저장소에 가드레일이 전혀 없을 때.
- **코딩 표준**: **리뷰어 에이전트**에게 강제할 새 규칙을 줘야 할까요? 기존 규칙을 제거하거나 명확히 해야 할까요? 먼저 위반을 분류하세요. **기계적** 위반(고정된 구문 패턴, 금지된 API, import 형태, 파일 위치 규칙)에는 결정적 검사를 붙이는 것으로 끝납니다. 저장소 자체 린터의 커스텀 규칙, 새 pre-commit 훅, 새 CI 잡 중 저장소의 언어와 기존 가드레일로 가장 싸게 되는 것을 쓰세요. 규칙을 쓰기보다 검사를 만드는 것을 기본으로 하세요. `CODING_STANDARDS.md`는 진짜 **판단이 필요한 사안**(파일 간 일관성, "주변 스타일과 맞는가" 등 어떤 가드레일로도 대체할 수 없는 것)에만 남겨 두세요. _사용 시점_: 리뷰어 에이전트가 실수를 잡지 못했을 때.
- **전역 AGENTS.md**: 코딩 표준(또는 자동 검사)으로 옮겨야 할 지시 사항이 있나요? _사용 시점_: AGENTS.md 파일이 특히 클 때. 저장소 범위든 사용자의 전역 범위든 해당됩니다.
- **도구 경제성**: 에이전트가 간소화할 수 있었던 비싼 도구 호출을 했나요? 토큰 효율이 유난히 낮은 커스텀 도구(CLI, MCP)가 있나요? _사용 시점_: 에이전트가 비싼 도구 호출을 했을 때.
- **무효 지시**: 에이전트의 행동을 바꾸지 못하는 지시가 조종용 파일에 있는지 찾으세요. _사용 시점_: 조종용 파일이 크고 다루기 힘들 때.
- **정보 접근**: 에이전트의 정보 접근을 늘릴 기회를 찾으세요. 개발 서버 로그를 tee로 노출하거나, 서드파티 서비스에 읽기 전용 접근을 주는 것 등입니다. _사용 시점_: 결정적인 정보를 에이전트가 얻을 수 없었을 때.

4. 이 후보들을 심각도 순으로 사용자에게 제시하세요.

## 참고

### 구현 대 리뷰

모든 작업은 구현과 리뷰의 두 단계를 거친다는 점을 기억하세요. 구현 에이전트는 **맥락 압박**이 가장 큽니다. 탐색, 코드 작성, 실패 디버깅을 모두 책임지기 때문입니다.

리뷰 에이전트는 맥락 압박이 가장 작습니다. diff를 받으므로 탐색이 필요 없고, 코드를 쓰거나 디버깅할 일도 대개 없습니다.

따라서 코딩 표준을 적용하는 책임은 구현 에이전트가 아니라 리뷰 에이전트에게 있어야 합니다.

### 파일

저장소에서 여러 파일을 쓸 수 있습니다.

- `CLAUDE.md`/`AGENTS.md`: 이 저장소에서 일하는 모든 에이전트의 컨텍스트 윈도우에 들어가는 파일입니다. 극도로 아껴 써야 하며, 대개 다른 파일로 가는 **탐색 포인터** 용도로만 씁니다.
- `CODING_STANDARDS.md`: 구현이 아니라 리뷰 중에 읽는 파일입니다. 표준 파일이 1,000줄을 넘으면 docs 폴더로 가는 **탐색 포인터**를 추가하세요.
- 문서: 다른 파일이 가리키는 참조 파일로 문서를 쓰세요. 새로 쓰기 전에 기존 문서를 먼저 찾아보세요.
- 스킬: 문서용(스킬의 description이 에이전트의 컨텍스트 윈도우에 들어가므로)이나 사용자가 호출하는 명령용으로 스킬을 쓰세요. `writing-for-agents` 스킬의 조언을 따르세요.
