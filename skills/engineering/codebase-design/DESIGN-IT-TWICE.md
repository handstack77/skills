# 두 번 설계하기

사용자가 선택한 깊게 만들기 후보에 대해 대안 인터페이스를 탐색하고 싶어 할 때 이 병렬 서브에이전트 패턴을 쓰세요. "Design It Twice"(Ousterhout)에 기반합니다. 첫 아이디어가 최선일 가능성은 낮습니다.

[SKILL.md](SKILL.md)의 어휘를 사용합니다: **모듈**, **인터페이스**, **이음매**, **어댑터**, **레버리지**.

## 절차

### 1. 문제 공간 설정하기

서브에이전트를 띄우기 전에, 선택한 후보의 문제 공간을 사용자용으로 설명하는 글을 쓰세요.

- 새 인터페이스가 충족해야 하는 제약
- 그것이 의존할 의존성과 그 범주([DEEPENING.md](DEEPENING.md) 참고)
- 제약을 구체화하는 대략적인 예시 코드 스케치. 제안이 아니라 제약을 구체적으로 보여 주는 수단일 뿐입니다

이것을 사용자에게 보여 준 뒤 곧바로 2단계로 넘어가세요. 서브에이전트가 병렬로 일하는 동안 사용자는 읽고 생각합니다.

### 2. 서브에이전트 띄우기

서브에이전트를 3개 이상 병렬로 띄우세요. 각자 깊어진 모듈에 대해 **근본적으로 다른** 인터페이스를 만들어야 합니다.

각 서브에이전트에는 별도의 기술 브리프(파일 경로, 결합 세부 사항, [DEEPENING.md](DEEPENING.md)의 의존성 범주, 이음매 뒤에 있는 것)를 프롬프트로 주세요. 이 브리프는 1단계의 사용자용 문제 공간 설명과 독립적입니다. 각 에이전트에게 서로 다른 설계 제약을 주세요.

- 에이전트 1: "인터페이스를 최소화하라. 진입점은 최대 1~3개를 목표로 하라. 진입점당 레버리지를 극대화하라."
- 에이전트 2: "유연성을 극대화하라. 많은 사용 사례와 확장을 지원하라."
- 에이전트 3: "가장 흔한 호출자에게 최적화하라. 기본 사례가 사소하게 느껴지도록 만들어라."
- 에이전트 4 (해당되는 경우): "이음매를 넘는 의존성에는 포트와 어댑터 중심으로 설계하라."

브리프에 [SKILL.md](SKILL.md) 어휘와 GLOSSARY.md 어휘를 모두 포함해서, 각 서브에이전트가 아키텍처 언어와 프로젝트의 도메인 언어에 맞게 일관되게 이름을 붙이도록 하세요.

각 서브에이전트의 산출물:

1. 인터페이스 (타입, 메서드, 파라미터, 그리고 불변식, 순서, 에러 모드)
2. 호출자가 어떻게 쓰는지 보여 주는 사용 예시
3. 구현이 이음매 뒤에 무엇을 숨기는지
4. 의존성 전략과 어댑터 ([DEEPENING.md](DEEPENING.md) 참고)
5. 트레이드오프: 레버리지가 높은 곳과 얇은 곳

### 3. 제시하고 비교하기

사용자가 하나씩 소화할 수 있도록 설계를 순서대로 제시한 뒤, 산문으로 비교하세요. **깊이**(인터페이스에서의 레버리지), **지역성**(변경이 모이는 곳), **이음매 배치**로 대비하세요.

비교한 뒤 자신의 권고를 내세요. 어떤 설계가 가장 강하다고 보며 이유는 무엇인지 말합니다. 서로 다른 설계의 요소를 조합하면 좋겠다면 하이브리드를 제안하세요. 소신 있게 말하세요. 사용자가 원하는 것은 메뉴가 아니라 강한 판단입니다.
