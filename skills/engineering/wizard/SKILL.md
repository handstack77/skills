# 마법사

**마법사**는 직접 손으로 하기에는 번거롭고 매번 AI에게 다시 설명하기에도 번거로운 수동 절차를, 사람에게 단계별로 안내하는 bash 스크립트입니다. 각 URL을 열고, 무엇을 클릭하고 복사할지 정확히 알려 주고, 값을 캡처하고, 필요한 곳(`.env`, GitHub 시크릿)에 쓰고, 매 단계에서 확인을 받고, 남은 단계 수를 보여 줍니다. 서드파티 서비스를 설정하거나, 일회성 마이그레이션을 실행하거나, 프로젝트를 한 상태에서 다른 상태로 옮길 수 있습니다.

멋진 UX는 이미 [template.sh](template.sh)가 해결했습니다. 단계별 진행 상황, 확인 게이트, (WSL을 포함한) 크로스 플랫폼 URL 열기, 숨겨진 시크릿 입력, 멱등적인 `.env` upsert, `gh secret`/`gh variable` 쓰기, 마무리 요약입니다. **당신의 일은 절차의 범위를 정하고 그 단계들을 작성하는 것뿐입니다.** `STAGES` 표식 위의 라이브러리는 모든 마법사에서 동일합니다. 그 일관성이 핵심이므로 절대 손으로 고치지 마세요.

마법사는 기본적으로 일회용입니다. 한 번 실행하려고 만들어 임시 경로나 `scripts/` 경로에 저장하고, 작업이 끝나면 삭제합니다. 저장소에 두어야 할 반복 가능한 설정 경로를 사용자가 원할 때만 커밋하세요.

## 절차

### 1. 절차의 범위 정하기

사람이 해야 하는 모든 수동 단계와 그 과정에서 캡처되는 모든 값을 파악하세요. 먼저 저장소를 읽고, 불쑥 묻지 마세요.

- 설정의 경우: `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, 프레임워크 설정, `.github/workflows/*` (모든 `secrets.*` / `vars.*` 참조는 마법사가 만들어 내야 하는 값입니다).
- 마이그레이션이나 전환의 경우: 현재 상태, 목표 상태, 그 사이의 되돌릴 수 없는 동작.

그다음 사용자에게 단계의 순서 목록과 각 단계가 만드는 값을 보여 주고 확인받으세요. 사용자가 추가, 제거, 순서 변경을 할 수 있습니다.

**완료 조건:** 모든 단계에 순서대로 이름이 붙어 있고, 캡처되는 각 값에 대해 (a) 사람이 어디서 얻는지, (b) 어디에 쓰는지(`.env`, GitHub 시크릿, 둘 다, 또는 어디에도 안 씀. 일부 단계는 순수한 동작입니다), (c) 시크릿(숨겨진 입력)인지 공개인지 알고 있습니다.

### 2. 각 단계의 여정 그리기

각 단계마다 사람이 따라갈 정확한 경로를 쓰세요. 어떤 URL을 열고, 거기서 무엇을 하고, 값이 어디에 표시되고, 어떤 변수를 채우는지. 예: "Dashboard → Developers → API keys → Reveal test key → 복사". 현재 UI나 정확한 명령을 실제로 모르겠다면 그렇게 말하고 사용자에게 묻거나 문서를 확인하세요. 존재하지 않을 수 있는 단계를 지어내지 마세요.

**완료 조건:** 모든 단계가 낯선 사람도 따라 할 수 있는 구체적인 지시로 이어집니다.

### 3. 마법사 작성하기

`template.sh`를 대상 경로로 복사하세요. 예시 단계를 단계마다 `stage` 하나씩으로 바꾸되, 의존성 순서로 배치합니다. 라이브러리 헬퍼를 사용하세요. `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm`. `TOTAL_STAGES`는 작성한 단계 수로 설정하세요.

템플릿이 세운 기준을 지키세요. 값을 묻기 전에 URL을 먼저 열고, 시크릿에는 `ask_secret`을 쓰고, 영속화되는 모든 값은 `write_env`로 쓰고, CI가 실제로 필요로 하는 값만 `set_secret`으로 설정하고, 되돌릴 수 없는 동작 전에는 `confirm`을 쓰세요. 각 `stage`는 화면을 지워서 현재 단계만 보이게 합니다. 사람이 필요로 하는 것이 스크롤되어 사라지지 않도록 단계 하나는 하나의 집중된 작업으로 유지하세요. 표식 위의 라이브러리는 건드리지 마세요.

### 4. 검증하고 인계하기

- `bash -n <script>`; `shellcheck`가 있으면 실행합니다.
- `chmod +x <script>`.
- 직접 끝까지 실행하지 마세요. 브라우저를 열고 사람의 입력에서 막힙니다. 대신 정적으로 추적하세요. 1단계의 모든 값이 캡처되어 1단계에서 말한 곳에 들어가고, 모든 `set_secret` 이름이 CI의 `secrets.*` 참조와 정확히 일치합니다.
- 사용자에게 실행 방법을 알려 주세요. 반복 가능한 설정 경로라면 커밋하고 README에서 링크해서, 다음 사람이 AI에게 묻지 않고 스크립트를 실행하게 하세요.
