# 스킬 메커니즘

[`writing-for-agents`](SKILL.md)의 스킬 고유 갈래입니다. 문서가 스킬일 때 달라지는 것(frontmatter, 호출 방식 선택, 라우터 스킬)을 다룹니다. 쓰기에 관한 나머지는 모두 `SKILL.md`의 보편 참고서에 있습니다.

## 호출

두 가지 선택이 있으며, 두 부하를 맞바꿉니다.

- **모델 호출형** 스킬은 `description`을 유지하므로 에이전트가 자율적으로 발동할 수 있고, 다른 스킬도 그것에 도달할 수 있습니다. 이름을 직접 입력할 수도 있습니다. 모델 호출은 언제나 사용자의 도달을 _포함_합니다. description은 에이전트의 발견을 더할 뿐 사람의 도달을 없애지 않습니다. description은 스킬의 최상위 컨텍스트 포인터이며 항상 로드된 채로 있어야 합니다. 발견 가능성을 얻는 대신 영구적인 컨텍스트 부하를 치릅니다. 내용이 전부 참고인 모델 호출형 스킬은 공유 참고의 한 집이기도 합니다. 다른 스킬이 호출할 수 있으므로, 여러 스킬이 필요로 하는 참고가 한 곳에 살게 됩니다. 방법: `disable-model-invocation`을 생략하고, 트리거 분기를 담은 모델용 description을 쓰세요(`SKILL.md`의 포인터 작성 규칙이 그대로 적용됩니다).
- **사용자 호출형** 스킬은 에이전트의 도달 범위에서 description을 걷어 냅니다. 이름을 입력하는 사람만 호출할 수 있고 다른 스킬은 호출할 수 없습니다. 컨텍스트 부하는 0이지만 인지 부하를 씁니다. 그것이 존재함을 기억해야 하는 색인이 당신입니다. 방법: `disable-model-invocation: true`로 설정하세요. `description`은 사람용이 되어, 한 줄 요약이며 트리거 목록은 걷어 냅니다.

에이전트가 스스로 스킬에 도달해야 하거나 다른 스킬이 그래야 할 때만 모델 호출형을 고르세요. 손으로만 발동한다면 사용자 호출형으로 만들고 컨텍스트 부하를 치르지 마세요.

두 사용자 호출형 스킬이 모두 필요로 하는 공유 참고는 어느 쪽에도 살 수 없습니다. description이 없으니 어느 쪽도 상대를 발동할 수 없습니다. 스킬 시스템 밖의 일반 파일로 밀어내세요. 어떤 스킬이든 가리킬 수 있는 외부 참고입니다.

## 호출 방식으로 쪼개기

쪼개기의 호출 방식 절단(순서 절단은 `SKILL.md`에 있음)입니다. 그것을 홀로 촉발해야 하는 별개의 선두 단어(프롬프트에서 실제로 쓰는 트리거 단어)가 있거나 다른 스킬이 그것에 도달해야 할 때 모델 호출형 스킬을 쪼개 내세요. 새로 항상 로드되는 description에 컨텍스트 부하를 치르므로, 그 독립적인 도달이 그만한 값어치가 있어야 합니다.

## 라우터 스킬

사용자 호출형 스킬이 기억할 수 있는 한도를 넘어 늘어나면, 쌓인 인지 부하는 **라우터 스킬**이 치료합니다. 다른 스킬들과 각각을 언제 찾을지 이름을 대는 사용자 호출형 스킬 하나여서, 사람이 여럿 대신 하나의 스킬만 기억하면 됩니다. 힌트만 줄 수 있고 발동시킬 수는 없습니다. 사용자 호출형 스킬에는 description이 없으니 사람 외에는 아무것도 그것에 도달할 수 없습니다.
