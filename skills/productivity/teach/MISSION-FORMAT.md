# MISSION.md 형식

`MISSION.md`는 작업 공간 루트에 있습니다. 사용자가 이 주제를 배우는 _이유_를 담습니다. 모든 교육 결정(다음에 무엇을 가르칠지, 어떤 자료를 보여 줄지, 어떤 연습을 설계할지)은 이 문서로 거슬러 올라가야 합니다.

## 템플릿

```md
# Mission: {Topic}

## Why
{1~3문장. 사용자가 쫓는 구체적인 현실의 목표. 이 기술을 갖게 되면 삶이나 일에서 무엇이 달라지는가? "X를 이해하기 위해" 같은 추상적인 틀은 피하고, 근본적인 결과를 끌어내세요.}

## Success looks like
- {사용자가 할 수 있게 될 구체적이고 관찰 가능한 일}
- {또 다른 구체적인 일}
- {…}

## Constraints
- {시간, 예산, 기존 약속, 학습 선호, 접근 방식을 제한하는 모든 것}

## Out of scope
- {사용자가 지금 당장은 쫓고 싶지 않다고 명시한 인접 주제. 근접 발달 영역을 보호한다}
```

## 규칙

- **작업 공간당 미션 하나.** 사용자가 서로 무관한 두 가지를 배우고 싶다면 작업 공간이 둘입니다.
- **추상보다 구체.** "10월까지 하프 마라톤을 뛴다"가 "체력을 키운다"보다 낫습니다. "팀에 Rust CLI를 출시한다"가 "Rust를 배운다"보다 낫습니다.
- **모호함에 맞서세요.** 사용자가 이유를 설명하지 못하면 무엇이든 쓰기 전에 인터뷰하세요. 나쁜 미션은 미션이 없는 것보다 나쁩니다.
- **현실이 바뀌면 고치세요.** 미션은 바뀝니다. 사용자의 목표가 움직이면 이 파일을 갱신하세요. 낡은 미션이 이후 세션을 이끌게 두지 마세요.
- **짧게 유지하세요.** `MISSION.md`가 한 화면을 넘어가면 나침반이 아니라 계획이 되기 시작한 것입니다.
